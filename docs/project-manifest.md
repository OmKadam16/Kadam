# Project Manifest (`kadam.json`)

A Kadam project is a directory containing a `kadam.json` manifest, one `.kdm`
file per page, and optional local assets. The manifest is the only place routes
are declared; `.kdm` files never contain route syntax.

```text
MyWebsite/
  kadam.json
  pages/
    home.kdm
    about.kdm
    contact.kdm
  components/
    Button.kdm
  assets/
    logo.svg
    hero.webp
    fonts/
  dist/                  generated by `kadam build`
```

## Schema

```json
{
  "kadam": "0.1",
  "name": "MyWebsite",
  "version": "1.0.0",
  "components": ["components/Button.kdm"],
  "pages": [
    { "title": "Home",    "source": "pages/home.kdm",    "route": "/" },
    { "title": "About",   "source": "pages/about.kdm",   "route": "/about" },
    { "title": "Contact", "source": "pages/contact.kdm", "route": "/contact" }
  ],
  "assets": "assets",
  "outDir": "dist",
  "basePath": ""
}
```

| Property | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `kadam` | string | no | — | UI language version: `"0.1"` or `"0.3"`. Files without a directive use it; a file directive must match it. |
| `name` | string | **yes** | — | Non-empty project name. |
| `version` | string | no | — | Project version label; not interpreted. |
| `pages` | array | **yes** | — | At least one page entry. Order defines diagnostic and emission order. |
| `components` | array | no | `[]` | Project-relative `.kdm` component sources. Order is not semantic. |
| `assets` | string | no | `"assets"` | Conventional asset directory. Relative and inside the project. |
| `outDir` | string | no | `"dist"` | Output directory, resolved against the project root. |
| `basePath` | string | no | `""` | Deployment prefix such as `"/my-site"`. Must start with `/` or be empty. |
| `siteUrl` | string | no | — | *kadam 0.3.* Absolute origin such as `"https://example.com"` (no path; use `basePath`). Adds canonical links, Open Graph URLs, share images, and `sitemap.xml`. |
| `breakpoints` | object | no | — | *kadam 0.3.* Extra min-width breakpoints, e.g. `{ "wide": 1440 }`, used as `on wide screens, ...`. Names are one lower-case word other than `phones`, `tablets`, `desktops`; widths are whole pixels from 1 to 10000; at most 8. |
| `fonts` | object | no | — | *kadam 0.3.* Local font files used as `the font is "Inter"`: `{ "Inter": { "source": "assets/fonts/Inter.woff2", "weight": "100 900", "style": "normal", "fallback": "sans serif" } }`. `source` is a project `.woff2` or `.woff` file (no remote fonts); `weight` defaults to `"400"`, `style` to `"normal"`, `fallback` to `"sans serif"`. Only fonts a page uses are copied. |
| `theme` | string | no | — | *kadam 0.3.* A `.kdm` file with a `theme { ... }` block of theme colors (`the brand color is #4F46E5`, `in dark mode, the brand color is #818CF8`), shared by every page and component (D-38). |
| `data` | object | no | — | *kadam 0.3.* Data names to project-relative `.json` files, e.g. `{ "projects": "data/projects.json" }`, used as `a ProjectCard for each project in projects` (D-40). Each file is an array of at most 1000 flat records (text, number, or true/false fields). At most 32 entries. |
| `connect` | array | no | — | *kadam 0.3.* Origins pages may load data from at run time, e.g. `["https://api.example.com"]` (D-41). Each is an `https` origin with no path (`http` only for localhost); at most 16. `kadam dev` sends them as `connect-src`. |
| `stylesheets` | array | no | — | *kadam 0.3.* Existing `.css` files whose classes elements may use with `it also uses the class "x" from "styles/legacy.css"` (D-42). Project-relative; at most 16. Only used files are copied and linked, before Kadam's CSS. |
| `strict` | boolean | no | `false` | *kadam 0.3.* Ban every escape hatch: raw css, stylesheet classes and externals (`KDM3053`), as `kadam check --strict` does. |

Unknown top-level keys and unknown page keys are errors, so a typo is never
silently ignored.

### Page entries

| Property | Type | Required | Meaning |
| --- | --- | --- | --- |
| `source` | string | **yes** | Project-relative `.kdm` file. `file` is accepted as an alias. |
| `route` | string | **yes** | URL route beginning with `/`. *kadam 0.3:* a `:field` segment (`/posts/:slug`) on a page made for each record takes that record's value. |
| `title` | string | no | Human title. When present it must equal the `page "..."` title in the source. |

Exactly one page per `.kdm` file; each source path may be declared once.

### Component entries

Each entry is a project-relative `.kdm` path. The declared component name, not
the file name, is authoritative.

- A component file contains exactly one `component` block and no page.
- A page file contains exactly one `page` block and no component.
- A path may not be listed twice, and no path may be both a page and a
  component (`KDM4008`).
- Paths follow the same containment rules as pages: inside the project, not
  inside `outDir`, no `..`, and no symlink escape.
- Component sources are compile inputs, not routes or assets. They are never
  copied into the output tree.
- Components are a project-mode feature. `kadam build page.kdm` has no catalog,
  so an instance there is an unknown component (`KDM3022`).

## Validation rules

The manifest loader (`src/compiler/manifest.ts`) emits `KDM4xxx` diagnostics:

- The file must exist, parse as JSON, and contain a top-level object.
- `name` is required and non-empty.
- `pages` is required, non-empty, and contains objects only.
- `kadam`, when present, must be exactly `"0.1"` (`KDM4004`).
- Source paths must be relative, end in `.kdm`, contain no `..`, and be unique.
- Routes must start with `/`, contain no `..`, `?`, `#`, backslash, or
  whitespace, and use URL-safe segments (`A–Z a–z 0–9 . _ ~ -`). Duplicate
  routes after normalization fail with `KDM4005`.
- `assets` and `outDir` must be relative and stay inside the project.
- `basePath` must start with `/` and must not contain `..`, `?`, or `#`.

Project-level checks then add:

- `KDM4002` — a declared page file is missing, unreadable, not a regular file,
  or escapes the project root (including through a symbolic link).
- `KDM4007` — a declared component entry is invalid, missing, unreadable,
  outside the project, inside the output directory, or not a `.kdm` file.
- `KDM4008` — a component path is duplicated, collides with a page path, a
  component file contains a page, or a page file contains a component.
- `KDM3011` — two pages declare the same title.
- `KDM4001` — a manifest `title` disagrees with the page title.
- `KDM3007` — a `go to page "..."` target does not exist in the project.
- `KDM4003` — a referenced asset is missing, has an unsupported extension,
  escapes the project root, or points at a Kadam source.

Every error is collected before any output is produced, so a project either
builds completely or writes nothing.

## Routes and links

Routes are normalized to a leading and trailing slash (`/about` → `/about/`);
the root route stays `/`. Each route becomes a directory-style document:

| Route | Output | Page stylesheet |
| --- | --- | --- |
| `/` | `index.html` | `assets/kadam.home.css` |
| `/about` | `about/index.html` | `assets/kadam.about.css` |
| `/about/team` | `about/team/index.html` | `assets/kadam.about-team.css` |

Navigation statements resolve a page title to its route at compile time:
`go to page "About"` becomes `href="/about/"`. Links, stylesheet URLs, and asset
URLs are root-relative, so they work from nested routes on any static host.
When `basePath` is set, every generated URL is prefixed with it. No client-side
router or server rewrite rule is required.

## Assets

Images referenced with `it shows "assets/logo.svg"` are copied byte-for-byte to
the same project-relative path under the output directory. Supported
extensions are `png`, `jpg`, `jpeg`, `webp`, `svg`, `avif`, `gif`, `woff`, and
`woff2`. Only referenced files are copied; each path is copied once no matter
how many pages use it. Fonts and images may live outside the conventional
`assets/` directory as long as they stay inside the project.

Image optimization, hashing, and rewriting are intentionally out of scope for
M3.

## Output directory safety

`kadam build` writes the whole site into a sibling staging directory and swaps
it into place with renames, so a failed build never leaves a partial site and
stale pages from earlier builds do not survive.

Because the output directory is replaced as a unit, the writer refuses to use a
directory that:

- is the project root or an ancestor of it;
- is the source directory (for single-file builds);
- contains `kadam.json` or any `.kdm` file;
- contains symbolic links.

## CLI

```bash
# Project build; output defaults to <project>/dist
kadam build --project ./MyWebsite

# Explicit output directory, relative to the current working directory
kadam build --project ./MyWebsite --out ./dist

# Deploy under a URL prefix
kadam build --project ./MyWebsite --out ./dist --base-path /my-site

# Single-page build (unchanged from M2)
kadam build ./page.kdm --out ./dist

# kadam 0.3 (F6, D-43): fragments for an existing page or CMS
kadam build --project ./MyWebsite --fragment --out ./embed
```

### Fragments

`--fragment` builds each page as markup to paste into an existing page,
instead of a whole site:

- `fragments/<page>.html` holds the page's elements inside
  `<div class="kdm-fragment kdm-page">`, with no `<html>`, `<head>`, `<title>`
  or metadata. It starts with a comment that lists the tags the host page adds
  to its `<head>`; the CLI prints them too.
- `assets/kadam.<page>.fragment.css` is Kadam's base CSS and the page CSS in
  one file. Rules for `body`, `html` and `:root` (the page background, text
  color and theme colors) apply to the wrapper instead, and every other rule
  without a Kadam class is prefixed with `.kdm-fragment`, so nothing in it can
  match the host page.
- A page with state, events or loaded data also gets its runtime
  (`assets/kadam.<page>.js`) and a scoped JavaScript-off stylesheet.
- Images, stylesheets and external modules are copied as in a normal build.
  Use `--base-path` when the files are served under a prefix.

Limits: the host's own CSS can still reach into the fragment (use Web
Components, D-43, for full isolation); a state kept in the address changes the
host page's address; links to other Kadam pages point at their site routes.

### Web Components

`kadam build <project> --target web-components` (kadam 0.3, D-43) builds every
component in `components` as a custom element, all defined in one module,
`kadam-elements.js`:

```html
<script type="module" src="/kadam-elements.js"></script>

<kadam-product-card name="Desk" price="120" link="https://shop.example/desk"></kadam-product-card>
<kadam-panel title="Hello" variant="compact">
  <p>Goes in the unnamed slot</p>
  <p slot="footer">Goes in the footer slot</p>
</kadam-panel>
```

- **Tags:** `ProductCard` becomes `kadam-product-card`; a library component
  adds its namespace (`kadam-studio-hero`).
- **Attributes:** each `text` or `url` parameter is an attribute. A missing
  attribute uses the parameter's default, or nothing. Values are written only
  as text and checked attributes: a `javascript:` URL is dropped, and markup in
  an attribute stays text. Changing an attribute re-renders the element.
- **Variants:** `variant="compact"` picks a variant; an unknown name uses the
  default body.
- **Slots:** `a slot` becomes `<slot>`, a named slot becomes
  `<slot name="...">`, and fallback content shows when nothing is slotted.
- **Styles:** each element has a shadow root, so host CSS does not leak in and
  Kadam CSS does not leak out. Page-wide text color, font and theme colors are
  set on `:host`, so the host can override a theme color on the element.
- **Events:** in a component, `when clicked, tell the page "select"`
  dispatches a `select` event (bubbling, composed) from the element. In a
  normal build the same sentence dispatches it from the component's element.
- Every component variant is checked like a page (types, accessibility,
  contrast) before anything is written.

Not yet: `image`, `length`, `color` and `page` parameters (`KDM3054`),
components with their own state or other events (`KDM3055`), custom fonts
inside shadow roots, and classes from `stylesheets`.
